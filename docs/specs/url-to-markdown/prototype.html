서버 컴포넌트는 정말 번들 크기를 줄여 줄까: 6개월 운영 후기

김하늘 · example.dev

지난 6개월 동안 결제 대시보드를 app 디렉터리 구조로 옮기면서 측정한 결과를 정리했습니다. 결론부터 말하면 초기 JS는 38% 줄었지만, 팀이 체감한 이득은 숫자와 달랐습니다.

측정 환경

  • 페이지 142개, 라우트 그룹 9개
  • Lighthouse 모바일, 4G 스로틀링, 3회 평균
  • 번들 크기는 gzip 기준 (412.7 KB → 255.9 KB)

가장 큰 함정

클라이언트 경계를 너무 위쪽에 두면 효과가 사라집니다. 아래처럼 경계를 말단 컴포넌트로 내리는 것이 핵심이었습니다.

// before
"use client"
export default function Dashboard() { /* ... */ }

// after
export default function Dashboard() {
  return <Chart /> // Chart만 "use client"
}
측정하지 않은 최적화는 의견일 뿐이다.
